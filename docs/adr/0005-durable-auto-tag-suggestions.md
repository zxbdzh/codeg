# 自动标签建议由共享后端调度，候选与正式标签分离持久化

自动建议必须在没有前端连接时继续处理成功完成的新轮次，并在重启或重新开启后恢复已有延后任务；同时，用户可能正在确认旧批次，而后台已经生成新批次。因此选择由共享 Rust 后端拥有调度与请求去重，把会话建议状态、候选批次和会话忽略偏好持久化，桌面与服务器共用同一条业务路径，不依赖前端挂载或进程内缓存维持正确性。

候选不是标签关联，继续遵守 [ADR-0003](./0003-ai-tagging-requires-confirmation.md)：只有用户确认才新建或贴标签。确认绑定具体批次，标签变更与该批次处理状态同事务提交，不能清空更新批次。保存候选及建议理由以恢复确认界面，不另存原始对话正文；显式忽略或用户主动移除所表达的会话级偏好跨重启保留。具体行为与验收以[自动标签建议规格](../features/ai-auto-tag-suggestions.md)为准。

## Considered Options

- **前端在轮次结束时发起请求，仅使用内存缓存**：改动较少，但浏览器断开、重复订阅、多窗口和重启会造成漏任务或重复调用，无法可靠保留用户处理状态。
- **候选直接写入标签关联，再让用户撤销**：存储更少，但未经确认就改变标签体系，违背已有人工确认边界。
- **保存全部历史建议作为待办列表**：方便追溯，但持续生成会积累重复待办；当前只需要最新候选和正在确认的有界快照，不引入历史批次产品。

## Consequences

- 需要新增持久状态、批次条件更新、租约／版本校验及事务服务，复杂度高于单纯启用设置开关。
- 状态事件仅用于提醒客户端回读；数据库状态是确认、忽略与恢复的依据。
- 这是设计定稿，不表示业务实现已经完成。
