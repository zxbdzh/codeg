# Web 远程开发与 Ego 接入：设计访谈

状态：首版范围与 V1–V11 已整体确认，关键能力验证与首版实现进行中；后台实验通过不等于实际无显示器整体验收通过。最近更新：2026-11-16。

## 用户目标

用户希望改善 Codeg 内置浏览器体验，使用自己的 Ego 浏览器；从 Codeg Web 端完成开发、观察和接管浏览器，以及 computer use，无须另开远程桌面查看执行过程。

2026-11-14，用户明确选择首版采用 Windows + 原版 Ego。“服务端无头”指不接物理显示器，允许保留后台图形会话；用户必须能在 Codeg Web 中直接看画面、接管浏览器和使用 computer use，不另开远程桌面。

用户随后选择共用现有日常 Windows 桌面，不将专用机器或虚拟机作为首版前提。

2026-11-15，用户进一步澄清 computer use 的范围：“直接 web 也可以复用桌面端的 computer use”。该部分以将桌面端既有能力开放给 Web 为目标，沿用现有窗口选择、授权、执行与停止语义；撤下上一轮新增“远程操控模式”的提案，不将其作为待决策事项。

Ego 的 Web 画面查看与人工接管仍按此前确认的需求保留。用户对 Agent 开发、验收不抢焦点的要求继续适用于本次工作，不能擅自将其转化成产品内新增的一套控制模式。

2026-11-15，用户选择页面级集成：Codeg 提供地址栏和标签页，在内容区域展示并操作 Ego 正在运行的真实页面；用户与 Agent 访问同一页面及其当前状态。

用户随后确认人工接管规则：点击或输入即触发接管，先暂停 Agent 的相关浏览器操作，再交由用户操作；只有用户点击“交还 Agent”后才继续。仅观看页面不打断任务。

用户在第六轮选择按 Codeg 会话独立组织页面：每条会话拥有自己的浏览器页面组，人工接管只暂停所属页面组的自动化，其他会话的页面组不因这次接管而暂停。

用户在第七轮选择共用当前 Ego 登录态，并再次明确页面和接管范围仍按会话独立。会话之间复用已有网站登录身份，不按项目或会话分别维护登录。

用户在第八轮选择任务完成后保留页面，直到用户主动关闭；下一轮继续使用原来的页面。原页复用针对 Ego 正常运行时的任务结束；注销和系统重启后的恢复由第十四轮单独确定。

用户在第九轮确认关闭 Web 或断网后，正在自动执行的浏览器任务继续运行，重连回到原会话和页面；已经人工接管的页面组仍保持暂停，只有用户点击“交还 Agent”后才继续。

用户在第十轮确认多端人工控制采用显式切换：新设备点击“接管到此设备”后获得控制，原设备变为只读，无需原端确认；Agent 仍保持暂停，直到用户点击“交还 Agent”。

用户在第十一轮确认关闭 Codeg 中的页面标签就真正关闭对应的 Ego 页面，其他设备同步移除；若 Agent 正在操作，先暂停所属页面组，等用户点击“交还 Agent”后再继续。关闭整个 Codeg Web 仍不影响后台运行。

用户在第十二轮确认首版打通 Web 文件往返：上传可选择当前电脑或手机上的文件，也可选择执行端项目文件；下载保留在执行端，按会话展示，并能从 Codeg Web 取回当前设备。

用户在第十三轮确认首版以 Windows 保持登录且未锁屏为运行前提，先保证不接显示器时能通过 Web 完成开发、查看和接管 Ego、复用 computer use。锁屏暂不列入首版保证范围。

用户在第十四轮确认注销或重启后先人工恢复环境：重新登录 Windows 并启动 Codeg、Ego，再从 Web 续接；保留会话、页面地址和已完成下载，恢复后等用户确认再继续任务，不要求恢复未提交表单等临时状态。

用户在第十五轮确认首版允许系统弹窗例外：Web 明确提示阻塞原因，确实无法通过 Ego 页面通道或现有 computer use 处理的，由用户在执行机处理后回来继续；网页内交互、文件选择和现有 computer use 仍按已定范围提供。

运行基线、注销重启恢复及系统弹窗例外记录于 [ADR 0007](../adr/0007-windows-ego-web-development.md)，页面级集成、登录态复用、页面归属、交接、保留、关闭、Web 断线行为及文件往返范围记录于 [ADR 0008](../adr/0008-ego-live-page-integration.md)。2026-11-15 用户已整体确认首版范围与验收清单，授权先验证后实现。

## Ego 的已知边界

本节外部资料及本机版本核查于 2026-11-14。

- 本机 `ego-browser --version` 输出 `0.6.2.8`；`ego-browser skill` 可正常读取。
- 当前安装版本的指南列出 TaskSpace、页面操作、截图、CDP、`handOff()` 与恢复控制等能力。这些能力不能直接证明存在 Web 远程画面或无人值守运行能力。
- [Ego 官方仓库](https://github.com/citrolabs/ego-lite) 当前说明支持 macOS 和 Windows，Linux 仍在路线图中。不能将原版 Ego 的 Linux 支持作为现成前提。
- [官方自定义 Agent Harness 接入指南](https://lite.ego.app/document/en/docs/custom-agent-harness) 明确要求命令能在安装 Ego 的机器上执行；远程、容器和云运行环境需要宿主执行桥。仅加载 skill 不会建立这条连接。
- [官方快速上手指南](https://lite.ego.app/document/) 将观察与接管描述为进入 Ego 的 Space。将这种交接搬到 Codeg Web 内，仍须验证并实现对应通道。
- 本轮未验证 Ego 在无显示器、锁屏、用户注销、独立图形会话或服务器重启后的行为，也未验证浏览器界面、系统弹窗与网站画面的捕获范围。

## 决策树

按依赖逐项确认，每次只向用户提出一个决策；只有已经确认的结论才进入 ADR，已经定清的领域术语才进入 `GLOSSARY.md`。

1. **已确认**：第一版采用 Windows + 原版 Ego，共用现有日常桌面，不以独立机器或虚拟机作为前提。
2. **已确认**：“无头”允许后台图形会话，不接物理显示器；首版以 Windows 保持登录且未锁屏为前提，锁屏状态不列入保证范围；注销或重启后由用户重新登录并启动 Codeg、Ego，保留会话、页面地址及已完成下载，确认后续跑，不保证网页临时状态恢复。
3. **已确认**：使用原版 Ego，并复用用户当前 Ego 的网站登录态；页面组织与接管范围按 Codeg 会话独立。
4. **已确认**：采用页面级集成，Codeg 的地址栏和标签页组织 Ego 的真实页面，支持 Web 内查看与操作；网页内交互、文件选择和已有 computer use 在既定范围内提供，确实无法处理的系统弹窗明确显示阻塞原因，由用户在执行机处理后回来继续。
5. **已澄清**：Web 复用桌面端现有 computer use 能力及其授权、前后台输入和停止语义；不新增远程操控模式，不据此扩大为完整桌面的人工远控需求。
6. **规则已确认，待技术验证**：每条 Codeg 会话拥有独立页面组，接管暂停所属组的浏览器操作，仅显式“交还 Agent”后恢复，其他组可继续；登录态共用当前 Ego，任务结束保留原页面直到用户主动关闭，下一轮继续复用；Web 断线后自动化继续运行、人工接管组仍暂停，重连回到原会话和页面；多端观看、同组单端人工操作，通过“接管到此设备”显式切换且无需原端确认；关闭页面标签会真正关闭 Ego 页面并同步各端，先暂停正在操作的所属组，显式交还后才继续；恢复时的状态一致性及未完成动作处理待技术设计。
7. **文件范围已确认，开发闭环待整体验收**：首版支持从当前设备或执行端项目选择文件上传到网站，网站下载保留在执行端、按会话展示并可从 Web 取回当前设备；结合既有会话、项目文件、终端和开发预览能力，验证修改项目、启动服务、在 Ego 查看结果及继续修正的完整流程。
8. **已确认并推进**：以已选范围与验收清单作为首版基线，先验证关键能力，验证通过后按该范围实施；技术细节由核查和原型确定，只有影响已选需求的取舍才重新提问。

## 已确认：第一版运行基线

用户选择 Windows + 原版 Ego，首版不以 Linux 独立运行作为验收基线。无显示器开发允许后台图形会话存在，Web 内观察与接管是明确要求。

第十三轮进一步确认首版保持 Windows 登录且未锁屏；在这一前提下验收无物理显示器时的完整 Web 开发流程。锁屏状态暂不列入首版保证范围。

这次确认不代表 Ego 已经通过无显示器实测，也不代表已经选择画面传输、输入转发或图形会话管理方案。

## 已确认：共用现有日常桌面

用户在第二轮选择 B，首版沿用现有日常 Windows 桌面承载 Ego 和 computer use，接受该选项对应的较低环境准备成本。

该选择仅确认沿用现有执行环境。根据 2026-11-15 的澄清，computer use 的授权和输入行为复用桌面端现有逻辑；不将先前建议的独立开发环境或新的前台控制模式作为实施前提。

## 已澄清：Web 复用桌面 computer use

用户在第三轮纠正了问题范围：需要的是 Web 能复用桌面 computer use。此前关于“新增远程操控模式”与“Agent 永远仅后台”的选择题撤下，不能将其中任一选项视为用户选择。

该部分的验收应围绕桌面已有能力在 Web 中可用、操作执行于同一目标 Windows 环境、授权和停止状态一致展开。具体入口、事件同步和生命周期方案在实现前继续核对。

## 已确认：Ego 页面级集成

用户在第四轮选择 A：页面级集成，直接在 Codeg 里看和操作 Ego 的真实页面。

Codeg 提供地址栏与标签页操作；页面内容、登录状态与交互状态来自执行端的同一 Ego 页面，人工输入也作用于该页面。Agent 与用户共享这一实际页面，而非分别打开同一 URL 的两个页面。

该决定确认用户体验与页面身份约束，尚未选定画面传输、输入协议或 Ego 适配实现。Ego 自身完整窗口不是本次选择的主要展示形式。

## 已确认：操作页面即接管，显式交还后继续

用户在第五轮选择 A，并明确要求先暂停 Agent 的浏览器操作，等用户点击“交还 Agent”后再继续。

交互顺序为：观看页面时 Agent 可继续操作；用户点击或输入时，先暂停相关浏览器自动化，再向同一 Ego 页面交付人工输入；用户完成后显式交还控制权，Agent 再继续。

用户未显式交还时，不以空闲超时、页面失焦或连接重建作为恢复自动化的依据。恢复时需使用人工操作后的真实页面状态；已发出动作的收敛、暂停确认与恢复适配仍需验证。

本规则只涉及 Ego 浏览器的人机交接。computer use 继续复用桌面端既有行为。接管范围已确定为所属 Codeg 会话的页面组，多端人工控制规则见第十轮决定；页面组与 Ego Space 的具体映射，以及控制权切换、重连时的状态同步实现，仍需后续验证。

## 已确认：按 Codeg 会话独立组织页面

用户在第六轮选择 A：每条 Codeg 会话拥有独立的浏览器页面组，而不按项目或全局合并页面。

人工接管其中一个页面时，暂停该会话页面组内的自动化；其他会话的页面组不因该次接管而暂停。用户显式交还后，该组的相关自动化才可继续。

页面归属与接管范围按会话独立；网站登录态的复用由第七轮单独确认。页面组与 Ego Space 的具体映射及其生命周期仍需验证。

## 已确认：共用当前 Ego 登录态

用户在第七轮选择 A：共用当前 Ego 的登录态，页面和接管范围仍按会话独立。

各页面组复用用户已经在 Ego 登录的网站身份，不为每个项目或 Codeg 会话另建独立登录要求。共用登录态不会合并不同会话的页面，也不扩大人工接管所暂停的范围。

具体 Ego 资料关联方式和兼容性仍需验证；这一决定不包含将其他浏览器资料全量复制或同步的需求。

## 已确认：任务结束保留页面，下一轮继续复用

用户在第八轮选择 A：任务完成后保留页面，直到用户主动关闭，下一轮继续使用原来的页面。

任务管理的页面继续留在所属 Codeg 会话的页面组中，不因一轮 Agent 任务完成而自动清理，也不只保留结果页面。下一轮复用原来的实际页面及其当前状态，而不是重新打开相同 URL。用户按需主动关闭页面。

原版 Ego 指南默认的任务结束清理不能直接用作本集成的页面生命周期规则；适配时须验证 TaskSpace 生命周期、保留页面及后续恢复操作的能力。页面组与 Ego Space 的映射仍未确定。

本决定针对 Ego 仍正常运行的情况；锁屏状态已由第十三轮排除在首版保证范围之外，注销和系统重启后的恢复按第十四轮决定处理，进程退出及崩溃时的状态一致性仍需技术设计。关闭范围只涉及任务管理的页面，不涵盖用户日常 Ego 中的其他页面。

## 已确认：Web 断线后继续运行，人工接管状态保留

用户在第九轮选择 A：关闭 Web 或断网后继续运行，重连回到原会话和页面；已经人工接管的页面组仍暂停，等用户点击“交还 Agent”后再继续。

Web 连接中断不结束正在运行的浏览器任务，也不清理所属页面组。执行端继续执行自动化，重新连接时展示原会话、仍存在的实际页面及最新进度；页面内容可以因断线期间的 Agent 操作而变化。

人工接管状态独立于 Web 连接保留。用户未显式交还时，相关页面组持续暂停；断开或重连都不能作为恢复自动化的依据。

本决定以执行端的 Windows、Codeg 和 Ego 仍正常运行为前提；多客户端之间转移人工控制权的规则见第十轮决定，注销和系统重启后的恢复见第十四轮决定，进程退出时的恢复适配仍需验证。

## 已确认：多端显式切换人工控制权

用户在第十轮选择 A：新设备点击“接管到此设备”后，原设备变为只读，无需原端确认；Agent 仍暂停，等用户点击“交还 Agent”再继续。

同一页面组允许多端观看，同时只有一个人工操作端。另一端已经人工接管时，新端需显式切换才能操作；原端断线也不阻止新端显式接管。切换成功后，原端只能观看，不能继续向该组交付人工输入或替新端交还 Agent；原端重连也不自动取回控制权。

切换设备仅转移人工控制权，相关 Agent 浏览器操作持续暂停，直到当前操作端显式交还。没有其他人工操作端占用时，仍遵循已确认的点击或输入自动接管 Agent 的规则。该决定不改变按 Codeg 会话独立的接管范围。

控制权切换与旧端输入的处理仍需实现和验证，不能仅凭界面显示只读就认为交接已可靠完成。

## 已确认：关闭标签即关闭真实页面

用户在第十一轮选择 A：关闭标签就真正关闭对应的 Ego 页面，其他设备同步移除；若 Agent 正在操作，先暂停所属页面组，等用户点击“交还 Agent”后再继续。关闭整个 Codeg Web 仍不影响后台运行。

关闭作用于执行端对应的实际页面，成功后从所属会话页面组及各客户端视图中移除。只读端须遵守既定的显式接管规则才能执行关闭；关闭某一页不会关闭该组其他页面，也不扩大到用户日常 Ego 中的其他页面。

若 Agent 正在操作，先暂停所属页面组，再执行关闭。关闭页面不构成“交还 Agent”；交还前保持暂停，不自动重建被关闭的页面。显式交还后，Agent 应依据页面已关闭的真实状态决定后续操作，不继续使用已失效的页面。
