## 用户操作

1. 在已保存的会话工具栏打开“文件检查点”。
2. 选择“启用并捕获基线”。默认关闭；启用后，同一目录中的会话在通过
   Codeg 发送下一条消息之前自动保存文件版本。也可以随时“立即捕获”。
3. 在快照列表中选择“预览”，查看当前内容、目标内容与新建、覆盖、删除数量。
   可以取消勾选文件，只恢复所选部分。
4. 选择“核对所选变更”，确认影响数量后“确认恢复”。
   处理期间禁用导航、快捷键、关闭弹窗等操作。
5. “预览撤销”生成上一次恢复的反向差异；仍需选择文件、预览并确认。
   停用自动捕获不删除已有快照；删除快照不删除工作区文件。

恢复只影响文件。不会改变会话消息、代理上下文、Git 历史、系统设置，
也不能撤销网络请求、数据库写入、提交、部署或其他工具的外部副作用。
启用前的历史会话没有对应文件版本，不能根据聊天记录推测重建。
共享工作目录的主线和旁支会看到同一份快照与文件变化。

## 范围与覆盖

这是 Codeg 管理的工作区快照，适用于经过统一发送入口的所有代理。
不调用 Claude、Codex、DeepSeek 或 Pi 的原生文件回退接口，
因此不把某个供应商是否具有 native rewind 作为文件恢复条件。
通过其他客户端或代理 CLI 直接发送的消息不会触发 Codeg 自动捕获。

工作目录由后端根据会话和所属文件夹决定，客户端不能提交任意磁盘路径。
目录规范化后按路径散列隔离存储，共用该目录的会话共享检查点。
快照位于应用数据目录的 `file-checkpoints/<workspace-hash>/`，
禁止将快照库放入被捕获目录中。

- 排除隐藏文件和目录、符号链接及 Windows reparse point。
- 遵循工作区的 ignore / Git ignore 规则，不继承工作区外层的忽略文件。
- 排除 `node_modules`、`vendor`、`venv`、`__pycache__`、`dist`、
  `build`、`target`、`coverage` 等生成目录。
- 单个文件上限 5 MiB，单次上限 5,000 个文件 / 100 MiB，
  扫描上限约 10 秒 / 20,000 个目录项。
  超限会明确失败，不会将不完整扫描标记为成功。
- 最多保留 50 个快照，捕获前后检查 500 MiB 内容库预算；
  超出预算后需要删除旧快照再继续。预览和最近一次撤销保留的备份另占空间。
- 二进制或超过 32,000 字节的文本只展示变更类型，不展示正文；
  仍可选中并恢复。Unix 可执行位纳入版本比较。

## 并发与恢复约束

发送与文件操作经过共享 admission gate；检查点操作还持有工作区文件锁，
防止同一数据目录被多个进程同时写入。
捕获、预览和恢复之前，检查同一目录及嵌套目录的 Codeg 会话是否有正在
执行的回合、工具、后台任务或委派。有任务在执行时阻止文件操作，不抢占输出。

自动捕获发生在统一 `send_prompt_inner` 的消息入队之前。
捕获失败则拒绝发送；消息不会进入代理，也不会留下粘住的回合占用标记。
默认未启用时维持原有发送行为，不因检查点目录限制而阻止发送。

恢复计划包含文件的预览前、目标内容散列，15 分钟后失效。
开始写入前先验证全部所选文件及备份，任何一个文件发生变化均拒绝整个计划。
逐文件替换前再校验一次；新目录和路径拒绝越界、设备名、隐藏组件及链接。
内容损坏、缺失、路径不安全和忽略范围发生变化均明确失败。

每次恢复先持久化现状备份与 journal，再用同目录临时文件逐个替换。
调用方断开后，后端任务继续持有 gate 至本次文件操作结束。
应用中断或中途失败时继续保存 journal 和内容，后续禁止新的捕获、恢复及删除，
要求先从“预览撤销”恢复已写入的文件。
中断恢复必须选择其反向计划的全部文件，避免丢失尚未恢复部分的日志。

撤销只接受最近一次恢复 ID。文件仍是恢复后的内容时才允许反向替换；
检测到更新内容则拒绝覆盖。快照删除和垃圾回收保留最近 journal 引用的内容，
因此不会同时破坏撤销数据。

Codeg 的 gate 无法冻结外部编辑器、独立 CLI 或其他进程。多文件恢复也不是
文件系统事务：外部进程仍可能在最后一次校验后写入；操作中断可能只完成部分
文件，因此必须保留 journal 并恢复。操作前应让共享目录中的其他写入暂停。
本阶段不提供多级撤销、工作树隔离、自动恢复对话上下文或跨机器快照同步。
