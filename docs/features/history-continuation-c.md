## 用户操作

1. 点击右侧栏“分叉会话”图标，搜索并选择自己发过的一条消息。
   用户消息旁的分叉按钮也使用相同流程。
2. 选择首条消息时，打开同目录、同代理的空白草稿；
   选择后续消息时，新会话只继承所选消息之前的历史。
3. 原话只进入新输入框，用户修改后自行发送。
   创建和打开分支期间，全局等待层阻止误操作。
4. 原会话、连接和草稿保留，通过原会话标签返回主线。

包括前一回合的回答与工具步骤。选择器显示对应说明。
含附件、尚未保存或缺少可识别前序回答的消息仍不支持历史分叉。

## 一致性规则

- 请求同时提交所选用户消息的原始文本、时间和代理消息 ID。
  后端重新读取源 transcript，核对角色和消息快照。
  `turn-N` 位置被压缩或重解析后复用时，陈旧选择会被拒绝。
  输入框解码后的显示文本不参与原始消息身份比较。
- 前端待重试请求绑定来源、位置和消息快照；相同位置的新消息不会复用旧请求。
- 原生 fork 返回新 session ID 后，后端读取新 transcript，比较预期历史前缀
  与新历史的全部角色和内容块。位置 ID、时间、用量等外层元数据不参与比较。
  检测到尾部复制、截断不足、其他分支或内容不一致时，不登记或打开成功分支。
- 日志可能晚于 ACP 响应落盘，后端最多等待约 5 秒重读。
  仍然无法读取或验证时明确失败，不把协议成功响应当作边界已经正确执行。
- 恢复日志保存所选消息和预期历史指纹。已知 S2 的恢复也先验证历史，
  再提交关系；老版本缺少边界凭据的历史恢复记录拒绝自动补登记。
  原有末尾分支恢复保持兼容。
- 原生创建结果未知时仍拒绝盲目重试；已创建但验证失败的 S2 保留恢复记录。
  ACP 没有通用、安全的删除契约，因此不自动删除代理原生 session。
- 旧 `acp_fork` 路径无法解析显式选择时也会报错，取消 resolver 的静默尾部降级。
  C 的新独立历史分叉路径另外执行结果历史校验。

校验采用严格匹配：适配器若重写正文或工具内容，可能导致可用历史被拒绝。
这种情况需要确认真实格式差异后再增加有证据的规范化，
不能通过忽略工具步骤或只比较最后一句来放宽校验。
已完成的旧关系不会在每次浏览时重新验证，也不被追溯标记为本阶段验收通过。
