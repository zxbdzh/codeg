# 首版采用 Windows 与原版 Ego，支持 Web 内无显示器开发

用户希望改善 Codeg 的内置浏览器体验，并在 Web 端完成远程开发。首版采用 Windows + 原版 Ego；“无头”定义为执行机器不接物理显示器，允许保留后台图形会话。

Codeg Web 必须提供 Ego 画面查看与浏览器人工接管，用户不需要另开远程桌面完成这些操作。这是体验要求，尚未限定底层画面和输入协议。

第十五轮确认一项首版例外：对于确实无法通过 Ego 页面通道或现有 computer use 处理、需要人工介入的系统弹窗，Web 明确提示阻塞原因，由用户在执行机处理后回来继续。网页内交互、文件选择和已有 computer use 仍须按既定范围提供，不能用此例外替代日常开发能力。

Ego 采用用户已确认的页面级集成，由 Codeg 的地址栏和标签页组织真实 Ego 页面，详见 [ADR 0008](0008-ego-live-page-integration.md)。

用户随后选择首版共用现有日常 Windows 桌面，减少独立环境的准备，不以专用机器或虚拟机为前提。

2026-11-15，第十三轮确认首版以 Windows 保持登录且未锁屏为运行前提。在这一前提下，不接物理显示器仍须能通过 Codeg Web 完成开发、查看和接管 Ego、复用桌面端 computer use。用户选择先保证该流程，锁屏状态暂不列入首版保证范围。

第十四轮确认注销或重启后采用人工恢复环境：用户重新登录 Windows 并启动 Codeg、Ego，再从 Web 续接。首版保留会话、页面地址和已完成下载，页面可按地址重新打开；任务等待用户确认才继续，不要求恢复未提交表单等临时状态。已有人工接管不因环境恢复被视为交还，已主动关闭的页面不重新出现。

2026-11-15，用户澄清 computer use 的目标是 Web 也能复用桌面端现有能力。该部分沿用已有窗口选择、授权、前后台输入与停止语义，聚焦复用和跨端可用性；此前新增“远程操控模式”的提案撤下。用户对本次 Agent 开发与验收不抢焦点的要求，不另行转化为产品的新控制模型。

该选择优先满足用户明确要求的原版 Ego 使用体验。当前 Ego 官方支持 Windows 与 macOS，Linux 仍在路线图中，因此首版不将 Linux 独立运行作为验收基线。证据及后续访谈见 [设计记录](../features/remote-development-ego.md)。

## Considered Options

- **Linux 单机优先**：直接面向独立服务器部署，但原版 Ego 的 Linux 兼容性尚不具备官方支持，可能需要改变浏览器选择。
- **Linux 主服务与独立 Ego 执行机**：可保留原版 Ego，但首版就需要处理两套运行环境及跨机连接。
- **专用 Windows 机器或虚拟机**：可以将开发操作与日常桌面分开，但需要额外运行资源；用户选择首版共用现有桌面。
- **首版同时保证锁屏可用**：将锁屏后的 Ego 画面、接管和 computer use 一并作为硬性验收项；用户选择首版先以保持登录且未锁屏为前提。
- **登录后自动恢复应用或无人值守恢复环境**：分别增加应用自启动，或图形会话与应用的自动恢复要求；用户选择首版人工恢复运行环境，从 Web 续接。
- **首版覆盖系统窗口人工接管**：将无法由页面通道或既有 computer use 处理的系统弹窗也纳入 Web 人工操作；用户选择明确提示阻塞并在执行机处理的首版例外。

## Consequences

- 首版无显示器运行须在保持 Windows 登录且未锁屏的条件下实测；锁屏不在保证范围内，注销或重启后由用户人工恢复环境，再通过 Web 确认续跑。
- 会话、页面地址和已完成下载及其归属需要持久保留；重新打开页面不保证恢复其原有临时状态，任务也不能因应用启动而自动继续。
- Web 页面预览、Agent 自动化工具或缩略图本身不足以满足用户明确要求的画面查看与人工接管。
- Web computer use 以桌面端既有行为为基线，复用授权与停止状态，不新增独立的前台控制模式。
- 当前独立 server 已有 computer use Web 接口，但桌面应用自带 Web 未接入其桌面服务实例；需打通复用链路，不能仅凭已有 HTTP handlers 判定目标完成。
- Ego 的页面级展示、人机交接、多端控制、页面生命周期及首版文件往返范围已确认，详见 ADR 0008；确实无法处理的系统弹窗按已接受的例外处理，恢复时的状态一致性及未完成动作处理需技术设计与验证。
- 系统弹窗例外需要明确的等待状态和可核实的阻塞原因；原因未知时如实显示未知，不能把尚未实现的常规能力归入例外或把未完成操作显示为成功。
- 2026-11-15，用户整体确认已选范围和 V1–V11 验收清单，授权先验证关键能力，通过后按确认范围实现；只有影响需求的新取舍再次提问。具体协议和适配方案仍由技术验证决定，不代表验收已通过。
