# Pane 切换与工作布局

状态：2026-11-13 用户已整体确认，功能已实现并完成下述验收，纳入本地版本 `0.43.0-local.3`。

Pane 和标签页组的定义见[术语表](../../GLOSSARY.md)。已确认的跨项目组合、会话归属、打开与移动行为以及后台运行规则见 [ADR-0006](../adr/0006-pane-conversation-ownership.md)。

## 本次范围

Pane 只管理会话区：会话、标签页组及其分屏布局。文件页签和终端继续沿用现有组织方式，不随 Pane 分别保存或切换。

## 会话归属与导航

- 一个 Pane 可以组合不同项目的会话，已打开的会话同一时间只属于一个 Pane。
- 从会话列表打开已在某个 Pane 中打开的会话时，跳到其所属 Pane 并激活该会话。
- 关闭会话标签页即解除归属，历史仍保留，下次打开时加入当前 Pane。
- 切换 Pane 不影响任务执行，原 Pane 的任务继续后台运行，停止由用户单独操作。

## 与文件夹设置的关系

会话区按当前 Pane 组织，切换项目不隐藏其中其他项目的会话。现有“标签页跟随文件夹”设置不再用于过滤 Pane 中的会话，文件页签仍沿用该设置原来的行为。

## 已确认的切换入口

Pane 切换栏放在中央区域顶部，独立、紧凑，显示各 Pane 的名称和新建用的“＋”。下方保留现有会话标签栏。

## 创建与命名

点击“＋”直接创建一个空 Pane 并切换过去，原 Pane 的会话和布局保留。

Pane 默认按序命名，例如“Pane 1”“Pane 2”；创建后可以重命名。

## 移动会话

本次先提供会话标签的右键菜单入口：右键会话标签，选择“移动到 Pane”，再选择目标 Pane。跨 Pane 拖拽留待后续考虑。

移动完成后，自动切换到目标 Pane，并激活被移动的会话。

## 移除 Pane

移除 Pane 时关闭其中的会话标签页，并解除这些会话的 Pane 归属。历史会话保留，以后从会话列表打开时加入当时的当前 Pane。

正在执行的会话任务继续在后台运行，停止仍由用户单独操作。

## 保存与恢复

自动保存 Pane 的名称和顺序、会话归属、标签页组、分屏布局及选中的会话标签。重新打开 Codeg 后恢复这些工作布局，并回到上次所在的 Pane。

## 多端同步

桌面端和 Web 端连接同一个 Codeg 服务时，Pane 名称、会话归属和分屏布局保持一致。

用户要求优先采用较简单的方案。现有已持久化会话的选中状态会跨端同步，独立查看位置需要额外拆分本地选中与共享状态，并补充恢复和远端变更后的回退逻辑。因此本次沿用联动：同一服务的当前 Pane 和选中的已持久化会话也同步，不新增每个窗口独立查看位置的能力。

## 自动收起与悬浮展开

切换栏平时收起为中央顶部的小胶囊，显示当前 Pane 的短名，长名称截断；鼠标靠近时像灵动岛一样展开。

已确认采用悬浮展开：展开时暂时覆盖中央区域顶部的一小块内容，不为切换栏增加占位行，不推动下方现有会话标签栏或会话内容。

以下交互细节已随整体草案确认：

- 鼠标进入小胶囊附近的有限区域时展开。
- 展开后显示 Pane 名称和“＋”；鼠标仍在操作区内时保持展开，离开后稍作延迟再收起。
- 鼠标移向现有会话标签时，触发区域不应覆盖整条标签栏。
- 动画可随鼠标返回而中断或反向，避免必须等动画结束才能操作。
- 键盘聚焦时也能展开；触屏通过点击操作，不依赖悬停。
- 外壳按真实宽高连续开合，收起与展开的内容分别淡入淡出，文字保持原始字号；圆角使用明确的像素值，避免整体缩放拉扁文字或极大圆角值插值跳变。

## 已确认的默认行为

以下默认行为已由用户整体确认：

- 首次启用时创建“Pane 1”，将当前已打开的会话、标签页组和分屏布局整体保留到其中。
- 始终至少保留一个 Pane；仅剩一个时不提供移除操作，仍可关闭其中的会话标签页。
- Pane 名称的右键菜单提供重命名和移除入口。
- 移动会话时加入目标 Pane 上次使用的标签页组；该组不存在时加入第一个组，保留目标已有标签顺序和分屏排列。
- 移除当前 Pane 后切到相邻 Pane；仅当源标签页组已空时，按现有规则收拢源分屏。
- 未发送的新会话标签和输入内容沿用现有本机草稿保存方式，切换 Pane 不清空；含未发送内容的 Pane 在移除前提示确认。
- Pane 名称过多时在展开栏内横向滚动，保持单行，不挤动会话标签栏。

## 实现需要满足的约束

- 复用现有标签页组和分屏树的能力，将各 Pane 的会话归属及布局纳入同一服务的共享持久状态；仅保存客户端本地布局无法满足同步要求。
- 会话归属和布局更新须保持一致，处理多端同时移动、移除和布局更新时的过期状态，避免一条会话同时出现在两个 Pane 或覆盖其他端的新修改。
- 从 Pane 移除标签页不能等同于取消运行任务；需要保留独立于会话视图的任务生命周期。
- 跨端同步查看位置时沿用现有未发送草稿和本地新会话的保护，不能用远端快照清掉本机输入。

## 验收场景

- 同一 Pane 同时打开两个项目的会话并分屏；切换项目后两条会话仍可见。
- 两个 Pane 保留不同会话和分屏排列，来回切换后分别恢复。
- 点击其他 Pane 的已打开会话会跳到其所属 Pane；关闭后从另一个 Pane 重开则归属当前 Pane。
- 右键移动会话后切到目标 Pane 并激活它，目标已有布局保持；任务和输入内容不因移动丢失。
- 会话生成过程中切换或移除其 Pane，任务继续后台运行；历史可重新打开，停止仍须单独操作。
- 新建、重命名、移除和重启恢复符合上文规则；文件页签和终端保持现有行为。
- 桌面端与 Web 端连接同一服务时，Pane 名称、会话归属、布局及查看位置同步，多端操作不会重复归属或用过期布局覆盖新状态。
- 悬浮栏收起显示短名、靠近展开、离开收起，整个过程不推动现有布局；键盘和触屏也能操作。

## 实现与接口

前端以 `ConversationPaneState` 保存各 Pane 的组和标签归属，沿用现有分屏树。会话视图以 `paneId/groupId` 区分容器，未显示的 Pane 保持挂载，避免切换时重建会话连接。

复用 `list_opened_tabs`、`save_opened_tabs` 和 `tabs://changed` 的同一版本及事务。保存请求新增可选 `paneState`；读取、保存响应及事件以 `pane_state` 返回，内部字段均为 camelCase：

- `schemaVersion`、`activePaneId`、`nextOrdinal`、`panes`。
- 每个 Pane 包含 `id`、`name`、`layout`、`assignments`、`selection`、`tileByGroup`、`active`。
- 共享标签标识使用 `conv-{folderId}-{agentType}-{conversationId}`，草稿标识和输入只保存在本机。

服务端验证唯一归属、布局结构、引用及版本；过期写入返回当前状态，不覆盖新布局。旧客户端未提供 Pane 状态时保留已有布局，并按真实标签清理失效关联；级联删除及项目移动同样规范化归属。

共享空分屏可能承载另一端未发送的草稿，不能因本机没有其成员就移除。恢复本机草稿时只补缺少的组，避免把整棵旧布局覆盖回共享状态。首次读取失败后，重连仍须完成 Pane 初始化。
