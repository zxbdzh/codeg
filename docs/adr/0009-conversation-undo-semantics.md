# 原会话撤回保留身份，不能用历史分叉替代

用户要求 Undo 在原会话生效，而不是复制新会话；同一会话后续继续时不能重新使用已撤回部分的上下文。原会话撤回与历史分叉保持独立，不能通过只隐藏界面历史或暗中 Fork 冒充支持。

任意已保存的用户消息都可作为撤回起点，包括一轮中途追加的指令；撤回选中消息及后续内容，保留之前的对话。用户已确认这一适配目标，不将撤回起点限定为每轮首条用户消息；各 Agent 的精确定位和安全撤回能力仍须工程核实。

如果暂时无法精确撤回到所选消息之前，则暂停本次撤回，保留历史并说明原因，不扩大撤回范围。这一边界已由用户确认，以保证撤回能力受限时仍保留选中消息之前的对话。

Undo 只撤回对话，不恢复工作区文件；文件恢复作为独立功能处理。这一边界由用户于 2026-11-17 明确确认。

用户同日确认，撤回后须将选中消息的文字、图片、附件和资源引用完整回填到输入框，保持未发送。输入框已有草稿时，先复用输入框收藏完整保存其文字和附件，再回填撤回的原输入，以便用户随后取回原草稿。

为保证完整回填，真正撤回前须检查附件；附件缺失且没有可恢复副本时，暂停操作并列出缺失项，保留当前对话和草稿，补齐后再撤回。

上传或粘贴的附件须使用发送时的版本，不能用后来修改的源文件内容替代；找不到原版本时列出问题并暂停撤回，工作区文件保持不变。文件引用则保留原路径，再次发送时使用目标文件的当前内容；两者的版本语义已由用户分别确认，恢复附件不等同于恢复工作区文件。

全部已接入 Agent 都纳入本轮适配目标，逐个核实能力、实现并真实验收，通过后开放 Undo；这一范围已由用户确认。为覆盖缺少原生撤回接口的 Agent，用户允许 Codeg 在成功备份后直接调整原会话历史，仍须保留原会话身份，并验证重启、续聊后不会重新出现已撤回上下文。各 Agent 的实际可行性和具体实现仍需工程核实。

会话正在运行时，由用户确认后先停止任务，确认停止成功后才撤回，避免仍在执行的任务继续写入旧上下文；停止失败或超时则保留历史，不继续撤回。这一行为已由用户确认。

停止范围包括当前会话仍会返回结果的后台任务和委托子任务，确认框须列出这些任务；全部停止后才撤回，任一停止失败或超时则保留历史。其他会话的任务不受影响，不能仅因工作目录相同就将任务视为属于当前会话。

停止任务和执行 Undo 期间，暂时禁止当前会话发送，保留未发送内容，操作结束后由用户重新点击发送，不自动排队；其他会话照常使用。这一规则已由用户确认，避免新消息在停止和撤回之间进入当前会话。

确认后、提交撤回前发现其他客户端或原生 CLI 改动了同一会话时，取消本次撤回，保留最新历史并刷新，说明原因，由用户重新发起并确认 Undo；不自动将变化纳入本次已确认的撤回操作。这一冲突处理规则已由用户确认。

每次 Undo 都须确认，展示将撤回的消息范围，并明确提醒工作区文件不会恢复；空闲时也遵循这一规则，使用户在执行前能够核对撤回范围。这一行为已由用户确认。

用户确认提供“恢复上次撤回”（Redo），将刚才撤回的对话恢复到原会话，以便补救误撤回；文件恢复仍独立。发送新消息后 Redo 失效，仅编辑未发送的草稿时仍可 Redo，以免恢复旧对话时覆盖新产生的对话。刷新页面或重启 Codeg 后仍保留 Redo，避免一次刷新或重启就失去恢复入口。用于 Redo 的备份从撤回成功起保留 7 天，到期自动清理，当前有效对话和输入框收藏中的草稿不受影响；这一期限已由用户确认。

Redo 只恢复最近一次撤回，不做逐级恢复。连续 Undo 多次后，恢复目标为最后一次 Undo 之前的对话状态；这一范围已由用户明确确认。

Redo 备份统一放在会话运行端的 Codeg 数据目录，桌面模式保存在本机，服务器模式保存在服务器，按已确认的 7 天规则自动清理。

用户可以手动清理当前会话的 Redo 备份，须先确认；清理后该备份不再可用于恢复，当前有效对话、草稿和输入框收藏不受影响。这一行为已由用户确认。

Redo 仅恢复对话，保留当前草稿的文字和附件，不自动发送，也不自动取回 Undo 前收藏的草稿，避免恢复对话时覆盖用户正在编辑的内容；这一行为已由用户确认。
