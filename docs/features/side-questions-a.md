# A 阶段：轻旁问

> 2026-11-11 范围调整：旁问跟随当前对话的模型及推理强度，移除独立模型设置。
> 当前支持 Claude Code 和 Codex；后者使用当前提供方的 Responses API，
> 不支持将订阅登录凭据直接用于旁问。以下固定 Claude 和独立设置说明为历史记录。
>
> 旁问现支持粘贴、拖拽 PNG/JPEG/GIF/WebP 图片，以及 UTF-8 文本/代码附件。
> 图片使用原生视觉内容块，文本作为转义后的引用内容；不向模型提供本地路径。
> 每次最多 4 个附件，单文件 4 MiB、合计 8 MiB，文本合计 32,000 字符。
> 支持预览、移除、仅附件提问；来源切换或清空后，旧读取与回答均不能写回。
>
> 输入框与主对话复用 RichComposer、ComposerSurface、ComposerToolbar 和图片预览组件。
> 按用户要求，底部仅保留发送/取消按钮，移除附件按钮和“最近对话”入口；
> 默认引用当前会话的最近正文，选区引用仍可从主对话进入。

依据 `conversation-branches-research-2026-11-10.md` 的 A 阶段，
用户于 2026-11-10 授权实现并使用 Ego Browser 真实验收。

## 范围

- 在右侧栏提供临时问答，支持从对话选区打开或引用当前会话最近的正文。
- 旁问执行器固定为 Claude Code，复用隐藏的一次性会话，
  强制禁用工具、MCP 和会话持久化；来源可以是其他代理的会话。
- 上下文是明确标注的有限文本快照：最多最近 12 条用户/助手正文、
  12000 个 Unicode 字符；选区最多 8000 字符，问题最多 4000 字符。
- 每次请求独立；旁问问题、回答和取消不改变主会话连接、模型历史或输入草稿，
  不产生新的会话数据库记录，也不自动回填主线。
- 具备独立加载、取消、错误提示及来源隔离；不将临时旁问描述为完整上下文 fork。

完整研究分支、摘要回填、历史回退与文件恢复属于后续阶段。

## 接口

- `side_question_ask`：调用者生成 UUID，传问题、选区及正文快照，
  可携带独立 Claude 会话的模式和配置；返回回答及实际引用字符/消息计数。
- `side_question_cancel`：按请求 ID 取消。先取消后注册、重复请求、
  响应晚到和客户端离开均不得影响其他请求。
- `get_side_question_settings` / `set_side_question_settings`：读取和保存独立旁问配置，
  保存在当前后端数据库 `app_metadata.side_question_settings`，供桌面和 Web 共用。
- 桌面命令和服务器 HTTP 使用同一核心实现；模型调用仍走已有 ACP 配置。

## 验收

1. 从正文选区进入旁问，能查看明确的引用范围并发送问题。
2. 没有选区时引用最近正文；不带工具输出、思考块或系统消息。
3. 主会话正在运行或切换标签时，旁问结果不会串到其他会话。
4. 取消后不接纳晚到结果，后续请求可以正常开始；失败后可编辑并重试。
5. 中文输入法组合输入不误发；窄屏仍能看见问题、状态和操作。
6. 真实页面使用 Ego Browser 操作和截图；真实模型调用与模拟边界测试分开记录。

## 实施和验证记录

### 使用方式与实现

- 点击右上角辅助面板按钮（`Ctrl+E`），选择“旁问”页签；
  也可在主线正文中选中文字，点击浮条的“旁问”。
- 输入问题后点击“提问”或按 `Ctrl/⌘+Enter`。普通回车只换行，
  输入法组合期间不提交。
- 界面明确显示 `Claude Code · 无工具`、来源会话和实际引用计数。
  “设置 → 协作 → 旁问模型”可独立选择模型和推理档位，旁问标题栏也提供
  “模型设置”入口。模型列表来自现有 Claude Code 的实时配置探测。
  未覆盖的选项沿用 Claude 默认值，不复制来源会话的模型设置。
- 配置保存后从下一次旁问生效，后端在每次执行时读取，不依赖浏览器缓存。
  支持“使用智能体默认配置”，点击后保存可清除覆盖值。
- 有选区时仅发送选区，正文数组为空；没有选区时，在发送瞬间截取最近已完成正文。
  正在执行的回合、工具输出、思考和未发送草稿均不纳入引用。
- 每个来源仅保留临时草稿、选区和最后一问一答；各次请求不继承上一条旁问历史。
  切换来源、切走旁问页签、关闭侧栏和卸载均会取消挂起请求。
- 桌面和 HTTP 命令共用核心实现。取消注册表处理提前取消和重复 ID；
  one-shot 的启动清理守卫保证晚启动的连接也会断开。

### Ego 真实验收

使用同一 Ego TaskSpace，在独立数据目录和测试项目中启动本地服务器，
不使用生产会话或安装目录。以下问答经过实际 ACP/模型调用，不是 mock：

1. **最近正文**：主线建立测试代号后，旁问只收到 2 条正文、44 字符，
   返回正确代号。主线草稿、连接和整个会话详情 API 响应保持不变。
2. **真实选区**：鼠标拖选“已记录”，通过浮条进入旁问。
   实际 HTTP 请求为 `selection: "已记录"`、`context: []`；
   返回引用计数 3 字符，并明确表示无法仅凭选区知道项目代号。
3. **并发**：主线仍显示“进行中”时发送旁问；旁问只引用此前已完成正文，
   正确回答，主线随后也正常完成，连接没有断开。
4. **取消及重试**：单击取消后仅有 1 次 ask 和对应 cancel，不再意外重发；
   立即重试得到“重试成功”。切主标签或关闭侧栏同样取消请求；
   返回原标签显示取消状态，另一个标签的旁问草稿不串线。
5. **输入**：普通 Enter 没有发送请求；通过 Chromium IME 组合协议
   触发中文组合输入期间，`Ctrl+Enter` 也没有误发。
   这是浏览器组合事件验证，不宣称覆盖所有 Windows 输入法。
6. **窄屏**：Ego 宿主不保留视口模拟设置，因此改用同源真实
   `390×844` iframe 视口验证响应式抽屉。
   模型返回“窄屏测试成功”，输入框和提问按钮可见，无页面横向溢出。
7. **持久化隔离**：全部旁问完成后数据库仍只有原先 1 条主会话，
   外部 session ID 不变，主历史中不包含旁问问题或回答。
   并发验收主动发送的主线测试回合不属于旁问写入。

### 验收中修复的问题

Ego 发现取消按钮和提问按钮复用同一 DOM 节点时，取消会同步切回
`type="submit"`，本次点击的浏览器默认行为会意外再提交一次。
取消处理现在先调用 `preventDefault()`，再撤销请求所有权；
增加回归测试并重建前端，Ego 实测不再重发，旧取消响应也不覆盖新回答。
