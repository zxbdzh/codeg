## 行为与边界

- 在已完成会话末尾建立原生独立会话分支；原会话的 ID、连接、历史和草稿保持可用。
- 原会话运行中明确要求等待完成，避免把未提交的中间状态称为完整分支。
- 研究旁支使用正常会话标签，支持右侧分屏，不在辅助栏嵌套整个对话页面。
- 来源关系独立持久化，包含源/分支会话及 session ID、边界和可编辑摘要，
  不复用委派专用的 `conversation.parent_id`。
- “整理结论”生成有限正文摘要草稿；“带回主线”先保存用户选择的摘要，再追加到
  主输入草稿。主线运行时也不自动发送或自动排队，用户仍按原输入框操作发送。
- 重开会话及重启后端后恢复来源关系和摘要；关闭标签按现有连接生命周期清理。
- 研究旁支可使用普通工具，与主线共享工作目录；文件修改不会自动回滚。
- 从历史用户消息分叉时，选中消息之前的最后一条助手回复作为 ACP 锚点；
  原用户消息填回新分支输入框作为可编辑草稿，用户确认后自行发送。选择首条
  用户消息则打开同目录、同代理的新草稿标签，不继承历史，不自动发送。

任意助手回复定位与文件恢复分别属于 C/D。

## 实施和验证

### 使用方式

1. 打开一个支持原生 fork 的持久会话，等待当前回合结束。
2. 点击正文上方的一行操作栏中的“分叉会话”，在弹窗里搜索、选择自己发过的
   一条消息。列表只显示用户消息；新分支保留所选消息之前的上下文，原话回填
   到新分支草稿，修改后自行发送。默认打开普通会话标签。
3. 如需保留完整历史，在弹窗底部选择“从最新位置另开研究”。在旁支中继续研究，
   主会话可独立发送消息，彼此不接收另一边的新正文。
4. 研究结束后点击“带回结论”，在弹窗中手动编辑摘要，或点击“整理结论”生成草稿。
   关闭弹窗保留未保存编辑；整理进行中关闭弹窗会取消生成。
5. “保存草稿”持久保存摘要；“填入主线草稿”先保存，再追加到主输入草稿并关闭弹窗。
   发送仍由用户决定，原有草稿不会被替换。
6. 主线的“已有研究”菜单可点击标题重新打开会话，或点击右侧分屏图标。
   研究会话的操作栏显示“返回主线”和来源名称，可直接导航返回。
7. 在主线中悬停于一条已有用户消息，也可直接点击分叉图标。首条消息打开没有
   历史的新草稿；中间消息创建独立持久分支。未持久化、缺少可定位前序回复或
   含附件的用户消息不提供此操作，避免选错边界或丢失附件。

操作栏固定为一行；列表、共享目录说明和刷新操作收进菜单，摘要编辑按需打开，
避免挤占对话正文。连接中、未连接、只读视图与代理确实不支持 fork 分别提示，
原因放在禁用操作的提示及菜单中，不常驻“不支持”横幅。能力门控仍依据真实连接。

历史定位入口限定 Claude Code、Codex 与 DeepSeek，并依据当前连接的 fork
握手门控，执行器沿用来源会话的代理。无法定位历史消息时返回错误，不退到末尾。
摘要生成使用 A 阶段的无工具 Claude Code 路径及独立旁问模型设置。

### 连接与持久化

- 原连接不接收 Fork。另起临时 ACP 连接严格恢复源 session，只在该连接上原生 fork，
  得到独立 session ID 后持久化，再清理临时进程。
- 恢复不成功即报错，不降级为新空会话或全文拼接。
- 新会话和独立 `research_branch` 关系同事务提交，原行不写入，委派字段保持空。
- 请求编号持久幂等；失败重试沿用原编号，避免不确定响应造成重复 fork。
  浏览器按后端、来源会话和所选消息保留未完成请求编号，刷新或重连后再次创建仍
  取回同一结果；不同消息不会误取同一个分支。
  原生 fork 与本地数据库无法构成分布式事务，已有 S2 的失败落库通过恢复日志重试；
  结果未知时明确拒绝重复 fork，详见后端实施文档。
- 摘要上限 12000 Unicode 字符，保存后跨重启恢复；同一页面内未保存编辑也按会话保留，
  防止切标签或连接变化造成丢稿。取消生成先撤销本地所有权，晚到结果不覆盖编辑稿。
