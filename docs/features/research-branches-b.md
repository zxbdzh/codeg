## 行为与边界

- 在已完成会话末尾建立原生独立会话分支；原会话的 ID、连接、历史和草稿保持可用。
- 原会话运行中明确要求等待完成，避免把未提交的中间状态称为完整分支。
- 研究旁支使用正常会话标签，支持右侧分屏，不在辅助栏嵌套整个对话页面。
- 来源关系独立持久化，包含源/分支会话及 session ID、边界和可编辑摘要，
  不复用委派专用的 `conversation.parent_id`。
- “整理结论”生成有限正文摘要草稿；“带回主线”先保存用户选择的摘要，再追加到
  主输入草稿。主线运行时也不自动发送或自动排队，用户仍按原输入框操作发送。
- 重开会话及重启后端后恢复来源关系和摘要；关闭标签按现有连接生命周期清理。
- 研究旁支可使用普通工具，与主线共享工作目录；文件修改不会自动回滚。

历史回答定位与文件恢复分别属于 C/D。

## 实施和验证

### 使用方式

1. 打开一个支持原生 fork 的持久会话，等待当前回合结束。
2. 展开正文上方“研究旁支”，点击“创建旁支”，独立会话自动在右侧分屏打开。
3. 在旁支中继续研究。主会话可独立发送消息，彼此不接收另一边的新正文。
4. 研究结束后展开旁支的“研究旁支”面板，点击“整理结论”，或直接编辑摘要。
5. “保存草稿”持久保存摘要；“带回主线”先保存，再追加到主输入草稿。
   发送仍由用户决定，原有草稿不会被替换。
6. 主线的旁支列表可重新打开或分屏；旁支面板可导航返回来源。

模型能力依据当前连接的 fork 握手门控，执行器沿用来源会话的代理。
摘要生成使用 A 阶段的无工具 Claude Code 路径及独立旁问模型设置。

### 连接与持久化

- 原连接不接收 Fork。另起临时 ACP 连接严格恢复源 session，只在该连接上原生 fork，
  得到独立 session ID 后持久化，再清理临时进程。
- 恢复不成功即报错，不降级为新空会话或全文拼接。
- 新会话和独立 `research_branch` 关系同事务提交，原行不写入，委派字段保持空。
- 请求编号持久幂等；失败重试沿用原编号，避免不确定响应造成重复 fork。
  浏览器按后端和来源会话保留未完成请求编号，刷新或重连后再次创建仍取回同一结果。
  原生 fork 与本地数据库无法构成分布式事务，已有 S2 的失败落库通过恢复日志重试；
  结果未知时明确拒绝重复 fork，详见后端实施文档。
- 摘要上限 12000 Unicode 字符，保存后跨重启恢复；同一页面内未保存编辑也按会话保留，
  防止切标签或连接变化造成丢稿。取消生成先撤销本地所有权，晚到结果不覆盖编辑稿。
