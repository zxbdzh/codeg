# 自动标签建议

> 状态：需求及实现方案已与用户确认（2026-11-02），待实现。用户明确选择仅定稿文档，本轮不修改业务代码、不提交、不调用真实模型。

本文承接 [AI 打标签原始规格](./ai-tagging-auto-title-and-prompt-stash.md)中预留的自动建议能力。术语见根目录 `GLOSSARY.md`；人工确认边界继续遵循 [ADR-0003](../adr/0003-ai-tagging-requires-confirmation.md)，后端调度与持久化边界见 [ADR-0005](../adr/0005-durable-auto-tag-suggestions.md)。与原始规格中的自动建议占位描述冲突时，以本文为准。

## 已确认决策

### 1. 自动提出建议，用户确认后生效

用户选择“自动建议，确认后生效”：无需主动点击 AI 按钮即可获得候选，但候选不是已贴标签。AI 不静默添加、移除或替换标签关联，也不静默创建标签；用户确认后才执行标签变更。

这是对既有人工确认边界的延续，不替代 ADR-0003。

### 2. 持续更新，但限制频率

用户选择“持续更新，但限制频率”：每轮成功结束后检查，仅在内容有变化且达到最小间隔时重新生成候选，以跟随会话话题变化并避免每轮调用。

待确认候选只保留最新一批；确认框已打开时固定当前批次，详见决策 8。

### 3. 只随 Codeg 内的新交互触发

用户选择“仅处理在 Codeg 内交互的会话”：新会话或历史会话只有在 Codeg 内完成新一轮交互后才进入自动建议检查。仅打开历史会话、导入文件或外部会话文件变化，不触发自动生成；开启功能时也不批量补算历史记录。

### 4. 会话内轻提示，点击再确认

用户选择“会话内轻提示，点击再确认”：有待处理候选时，在会话标签区域显示“有标签建议”入口，点击后打开现有确认框。自动生成不自动弹窗、不发成功通知，也不反复提醒；建议未确认前不显示成已贴标签。

### 5. 同一会话自动生成至少间隔 2 分钟

用户选择“2 分钟”：同一会话连续两次自动生成标签建议至少间隔 120 秒，标签使用独立间隔，不与自动标题共用。到达间隔本身不构成无条件调用；内容变化仍是生成的必要条件。

间隔从请求发出时计时，成功与失败均计入，详见决策 22。

### 6. 首个成功完成的有效轮次立即生成

用户选择“首个成功完成的有效轮次”：开启自动建议后，会话在 Codeg 内完成首个有正文的有效轮次即检查并生成首次候选，不先等待 2 分钟。已有历史的会话续聊一轮同样适用；不要求累计 3 轮或 6 轮。此处“首次”指尚无自动生成记录的情况；恢复已有延后更新不绕过限频，见决策 15。

### 7. 限频期间的新内容到期合并更新一次

用户选择“到期合并更新一次”：成功完成的新轮次若落在 2 分钟间隔内，记录待更新状态，在满足间隔且会话不在生成回复时，按最新已完成内容更新一次。期间多个已完成轮次合并处理，不逐轮排队，也不因时钟到期而无条件反复调用。

例如 10:00 已生成建议，10:01 又完成一轮，之后没有继续交互，仍应在满足间隔后更新这一轮内容。应用重启后的恢复见决策 11，关闭后重开的恢复见决策 15，失败重试见决策 16。

### 8. 待处理候选只保留最新一批

用户选择“只保留最新一批”：未打开确认框时，新生成候选更新待处理内容，不堆积历史批次。确认框已经打开时，当前展示和勾选绑定该批次快照，不因后台产生新候选而跳变。

打开期间到达的新批次与当前批次相互独立，确认后的衔接见决策 17；旧批次提交时仍需重新校验当前标签状态和作用域。

### 9. 明确忽略的标签，本会话不再自动推荐

用户选择“本会话不再自动推荐它”：对某个候选明确执行“忽略”后，记住这条会话对该标签的否定意图，后续自动建议不再推荐该标签。此规则不因应用退出或候选批次变化而失效，不影响其他会话，也不妨碍用户手动贴该标签。

仅关闭确认框不算拒绝。部分采纳时未勾选只跳过本批，详见决策 10；逐个恢复忽略见决策 13。已有标签按 ID 识别，改名不解除忽略；同名作用域消歧见决策 21，未创建候选的身份延续见决策 25。

### 10. 部分采纳时未勾选只跳过本批

用户选择“仅跳过本批，不永久忽略”：勾选部分候选并确认成功后，该批次视为已处理；未勾选候选不继续保留为待办，也不记为明确拒绝。后续有新内容时仍可再次推荐，只有单独执行“忽略”才在本会话长期屏蔽。

此规则只处理当前确认的批次，不清除生成时间更晚的新批次。

### 11. 重启后保留候选并恢复已有延后更新

用户选择“保留并恢复”：尚未确认的候选在退出并重启后继续可见、可确认；已经因新对话产生但未执行的延后更新也恢复处理。恢复时仍遵守功能开启、调用间隔和会话不在生成回复等约束，不将重启视为一次新的无间隔首次生成。

恢复只针对已经产生的任务，不扫描或补算从未触发过的历史会话。明确忽略记录同样跨重启保留。中断在模型请求期间的任务通过过期占位和有限重试预算恢复，见后端调度契约。

### 12. 手动移除已贴标签，也停止本会话自动推荐

用户选择“本会话不再自动推荐”：用户主动从会话移除已贴标签，也视为对该标签的明确否定，后续不在这条会话自动推荐。它与明确忽略候选的抑制范围相同，不影响其他会话，也不妨碍用户以后手动重新贴上。

自动清理失效关联、删除标签定义等非用户主动移除操作，不据此推断用户拒绝意图。如何恢复推荐见决策 13。

### 13. 支持逐个恢复本会话已忽略的标签

用户选择“可按标签逐个恢复”：在本会话建议区域提供“已忽略标签”入口，可单独解除某个标签的推荐屏蔽。恢复不直接贴标签、不立即调用模型，也不解除其他标签或其他会话的屏蔽。

### 14. 关闭自动生成后保留已有候选

用户选择“保留，仍可手动确认”：关闭“自动标签建议”后，不再发起自动调用，但保留已经生成的未确认候选，仍可从会话内入口手动确认。已有标签关联和已忽略记录不受影响。

已有延后更新的暂停与恢复见决策 15；关闭前已经在途的请求结果见决策 20。

### 15. 重新开启后恢复关闭前已有的延后更新

用户选择“恢复这一个已有任务”：关闭期间暂停已有延后更新，重新开启后按调用间隔和会话空闲约束，处理最新已完成内容。不扫描其他历史会话，不将恢复任务视为可绕过限频的首次生成。

### 16. 临时故障最多自动重试一次

用户选择“临时故障最多自动重试一次”：网络超时、限流或服务端临时故障，等待至少 2 分钟再自动重试一次；密钥或模型配置错误不自动重试。再次失败后等待新交互或手动刷新，不持续后台循环调用。

标签建议失败不影响主会话，也不清空已有候选。重试仍遵守功能开关和会话空闲等约束；失败提示见决策 19。

### 17. 确认旧批次，不清除更新的批次

用户选择“保留 B 批，过滤重复后提示”：确认框固定展示 A 批期间，后台可以生成 B 批。确认 A 批成功后，只将 A 批标记为已处理；B 批过滤已经贴上或明确忽略的标签，若仍有候选，继续显示会话内轻提示，不自动弹窗。

不得仅按会话 ID 清空所有待处理建议，导致尚未展示的新批次丢失。

### 18. 手动获取建议也过滤已忽略标签

用户选择“手动建议也过滤”：主动点击 AI 按钮或“换一批”时，同样过滤本会话已忽略的标签。希望重新得到该候选时，先在“已忽略标签”中恢复，再刷新建议；手动直接贴标签不受限制。

### 19. 后台失败只在会话内显示状态

用户选择“会话内显示失败状态”：自动建议最终失败或配置不可用时，在建议入口显示对应状态，点击可查看原因、重试或前往设置。不发错误 toast，不污染主会话错误状态，也不清空已有候选。

### 20. 关闭后保留已经发起请求的成功结果

用户选择“保留这份已发起请求的结果”：关闭自动建议前已发出的请求，成功返回后仍保存为待确认候选，供用户手动处理。关闭后不再启动新请求，不自动重试，也不自动贴标签。结果仍须通过批次、配置及当前标签状态校验，不能让迟到的旧结果覆盖较新的结果。

### 21. 同名标签明确展示作用域，由用户选择

用户选择“分清作用域，让我选”：全局与当前文件夹存在同名标签时，按真实标签 ID 区分，在确认框中明确显示作用域。仅按名称命中而存在歧义时不默认勾选，不擅自优先某个作用域。

忽略既有标签同样绑定其实际身份，不因同名而屏蔽另一个作用域的标签。

### 22. 调用间隔从请求发出时计时

用户选择“请求发出时开始”：每条会话的 120 秒间隔从上一次请求发出时计算，成功和失败都计入；同一会话不并发启动两个标签生成请求。临时失败重试还须满足决策 16 的等待约束，不因请求已经耗时而缩短失败后的重试等待。

### 23. 主动换一批可跳过自动间隔，并重置后续限频

用户选择“允许，并重新开始自动间隔”：明确点击“换一批”可以绕过自动建议的 120 秒等待和内容缓存，新请求发出后重新计算后续自动间隔。普通打开已有候选不调用模型；同一会话已有请求进行中时共用该请求，不重复发起。

### 24. 提供不永久屏蔽的“跳过本批”

用户选择“增加跳过本批”：将当前批次标记为已处理，不贴任何标签，不增加长期忽略记录，也不清除更新批次。仅关闭确认框仍表示暂时离开，不处理当前批次。

### 25. 未创建候选的忽略延续到同名称同作用域标签

用户选择“同名称同作用域继续屏蔽”：尚未创建的候选按规范化名称＋作用域记录忽略；后来创建了同名称同作用域的标签时，原来的忽略意图继续有效，不因候选变成正式标签而再次推荐。已有标签按实际 ID 区分，另一作用域的同名标签不受影响；用户仍可逐个恢复。

## 已核实的实现基础

- 手动获取建议与确认应用已经分离，确认应用走事务并复用既有作用域校验。入口位于 `src-tauri/src/commands/ai_assistant.rs`。
- 设置字段为 `auto_suggest_tags`／`autoSuggestTags`，当前默认关闭，设置页开关禁用，尚无生产自动触发消费点。
- 自动标题已有成功完成轮的后台触发链路与完成轮正文快照，可作为后续自动建议设计的参考；目前标签建议仍读取磁盘会话详情。
- 标签建议缓存只存在于进程内，不能替代并发请求去重或用户处理状态；尚无持久化的待处理建议与拒绝记录。

## 已确认的实现方案

以下工程方案已由用户整体确认，仅作为后续实施契约，不表示业务功能已经实现。

### 沿用既有边界

- 默认关闭，由设置开关显式启用；不新增提供方、密钥或独立模型配置，沿用现有标签任务模型。
- 沿用主题优先的提示词、最早有效用户请求＋最近 N 轮有效正文的上下文，不引入新的摘要任务，不发送工具结果或思考过程。
- 已有与拟新建候选合计最多 5 条，按真实身份去重并过滤已贴、已忽略候选；不同作用域的同名标签不能仅按名字误合并。仅名称命中有歧义时，作为一个候选的作用域选项交由用户选择，不默认勾选。不再允许后端分别截取后最多返回 10 条的口径差异。新建候选仍默认不勾选，默认全局，可在确认框选合法作用域。
- 自动建议与自动标题分别调度；标题关闭、锁定或失败，不应导致标签建议被跳过。

### 后端触发与调度

1. 在 `acp/lifecycle.rs` 成功完成轮的路径，复用完成轮正文快照，合并磁盘历史后交给标签调度器；不靠前端组件挂载、列表渲染或轮询触发模型调用。
2. 每条会话只有一份最新待更新目标，包含最新已完成内容的指纹。首次立即执行，后续在满足独立的 120 秒间隔且会话不在生成回复时执行；轮次重复事件不新增调用。
3. 从请求开始记录限频时间，失败也计入，防止连续失败绕过间隔；临时故障至多追加一次自动重试，最早重试时刻不早于失败后 120 秒，且尊重服务方更长的限流等待。配置错误不进入自动重试循环。
4. 新内容到达时只推进最新目标，不逐轮堆任务。旧请求完成只能确认自己处理的目标，不能清掉请求期间产生的新内容；后者仍按间隔合并处理。
5. 开关关闭暂停待更新任务，不新发请求；重新开启或应用重启只恢复已有任务，不能扫描历史补算。崩溃遗留的在途任务释放过期占位后，按同一有限重试预算恢复，不无限重复。
6. 调度器与模型调用由共享后端拥有，以数据库实例隔离运行状态；桌面和服务器复用相同逻辑，浏览器断开、多窗口或重复订阅均不额外触发生成。

### 持久化与并发契约

使用三类独立记录，不把未确认候选混进 `conversation_tag_link`；具体表名与迁移编号在实施时沿用仓库约定：

| 记录 | 关键内容 | 生命周期 |
| --- | --- | --- |
| 会话建议状态 | 最新目标指纹、已处理指纹、请求开始时间、到期时间、重试次数、错误状态、请求占位及版本 | 每会话一份，跨重启恢复 |
| 建议批次 | 批次 ID、会话 ID、输入／配置版本、候选与理由、生成时间 | 后端只保留最新有效批次；打开的旧批次作为有界确认凭据保留，关闭／处理后清理，客户端消失则经租约到期回收，不提供历史列表 |
| 会话忽略记录 | 会话 ID、标签身份、显示名／作用域、忽略时间 | 跨批次与重启保留，用户可逐个恢复 |

- 已有标签用标签 ID 标识，重命名不自动解除忽略；不同作用域的同名标签互不屏蔽。尚未创建的候选按规范化名称＋候选作用域识别，后来出现同作用域同名定义时继续匹配该拒绝意图，不把用户绕回重复推荐。
- 建议理由随候选批次保存，以支持重启后原样确认；不写入标签定义、标签关联或筛选索引，也不留原始对话正文的额外副本。
- 同一会话手动和自动请求共用在途占位与缓存。普通打开优先读取已生成候选，不额外调用；明确“换一批”可绕过内容缓存和自动间隔，但不重复启动同一份正在生成的请求。手动请求也推进后续自动限频，避免刚刷新又被后台重复生成。
- 同一份输入已经确认、跳过或过滤为空时，不能因为读取入口、重启或重复事件又恢复成未处理提示；只有符合已确认触发条件的新内容、已有待更新目标或明确手动换批才产生新的工作。
- 输入指纹覆盖上下文、标签池与作用域、会话忽略偏好；配置版本覆盖提供方／模型、上下文设置与提示词版本，不把密钥写进日志或候选载荷。配置变化使旧缓存失效，但不单凭保存设置扫描或调用全部会话。旧配置的在途结果不得覆盖新配置结果。
- 请求占位／版本用原子校验取得，提交时再核对版本；较旧结果不能覆盖较新结果。成功但无剩余候选时，不保留“有标签建议”的假提示；失败保留此前有效候选，并单独呈现错误状态。

### 确认、忽略与前端契约

- 提供读取当前建议状态、确认某批次、忽略候选、读取／恢复忽略记录的共享核心入口，经 Tauri 与 HTTP 暴露；确认必须携带批次身份，不能只传会话 ID 后清空全部建议。
- 提交时重新校验会话存活、标签适用作用域、已贴与已忽略状态及新建同名冲突。标签变更与该批次处理状态在同一事务提交；失败不标记批次已处理，不留下孤儿标签。
- 同一批次重复提交应为幂等成功，不能再次创建标签；会话已删除或作用域失效时停止相关任务并按现有删除语义清理候选及忽略记录，不因后台任务将其恢复。
- A 批确认后，B 批仅按最新已贴／忽略状态过滤；尚有候选就保留轻提示。删除或变更作用域导致候选失效时，提示并刷新确认内容，不静默替换为另一个同名标签。
- 显式忽略、手动移除与恢复均以当前数据库偏好为准，使迟到的旧候选也会被过滤。手动重新贴标签不受限制，但不会悄悄解除屏蔽；解除屏蔽只走明确的恢复操作。
- 关闭确认框保持当前批次未处理；部分采纳成功按决策 10 处理本批。“跳过本批”处理全部不想采纳、但也不想永久忽略的情况；零勾选不伪装成成功贴标。
- 会话标签区域根据状态显示待确认、生成中或失败；“已忽略标签”入口独立于有无待确认候选。事件只用于通知状态变化，首次读取、重连与多客户端同步均回读后端状态，不依赖事件不丢失。

### 实施顺序与验收

1. 新增状态／批次／忽略记录迁移及事务服务，完成重启恢复和批次条件更新测试。
2. 接入完成轮快照、共享标签生成逻辑和后端合并调度，使用现有 `FakeAiClient` 测试；不实际调用付费模型验收。
3. 暴露双模式接口和状态事件，接轻提示、固定快照确认、逐个忽略／恢复及设置开关。
4. 执行针对性 Rust 与前端测试，再检查服务器编译路径、类型和国际化键一致性。

关键验收场景：

- 第一轮成功且有正文才生成；标题关闭不影响标签，失败轮／空轮／仅查看导入不触发。
- 120 秒内多轮合并；最后一轮后暂停聊天仍会到期补算；生成回复期间不抢跑。
- 多窗口和重放事件只产生一次请求；手动打开现成候选不重新计费。
- A 确认时 B 仍保留；迟到的旧响应不覆盖新响应，未处理的新目标不会被旧请求清除。
- 忽略／手动移除后不再推荐，跨重启保留；逐个恢复不贴标签、不立刻调用；部分未勾选不永久屏蔽。
- 关闭后不新调用，在途成功结果仍可确认；重开只恢复原有待办，不扫描历史。
- 临时故障只自动重试一次；持续故障不循环、不 toast、不清空旧候选、不影响主会话。
- 同名不同作用域不误贴、不误屏蔽；新建冲突整批不半成功，重复确认不重复创建或清空更新批次。
